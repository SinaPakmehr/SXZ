# Phase 02 — SXZ2 streaming and folder architecture

## 1. Research question
Can the exact generative codec operate on streams and directory trees without
holding an entire input in memory, while preserving safe restoration?

## 2. Motivation
A file-only proof does not establish operational behavior on larger datasets,
independent frames, or archives with directory names and empty entries.

## 3. Hypothesis
Independent bounded frames can retain correctness and use Deflate, raw storage
and optional model search as local choices. A manifest-based TAR stream can
restore folders exactly.

## 4. Experimental architecture
`pack_stream` frames input with headers, CRC and bounded lookback copy state.
`pack_folder` inventories a tree into a PAX TAR stream and reuses the stream
codec. Restore rejects unsafe member paths and publishes output atomically.

## 5. Mathematical methods
Reference anchoring, optional native scanning, local model/copy/backend
selection, and frame-local recurrence detection. Copy references are bounded
to already reconstructed output.

## 6. Dataset description
Historical stream and folder benchmarks used mixed public/private-like media,
documents, binaries and model-weight files. Those inputs are not redistributed;
aggregate results remain, but exact panel reconstruction is unavailable.

## 7. Baselines
ZIP/Deflate and raw or lightly tuned stream options. Model-off and model-on
profiles are distinct configurations and must not be pooled.

## 8. Experimental protocol
Process frames independently, decode the full archive, compare hashes, and
record size and time. Directory tests also cover Unicode names, empty
directories, large numeric fields and malicious member paths.

## 9. Evaluation metrics
Restored bytes and SHA-256, archive bytes, throughput, frame counts, and the
number of fallback and model codecs per frame.

## 10. Quantitative results
The historical roughly 39 GB folder benchmark used `scan_budget=0`; it
therefore measured fallback/container behavior, not mathematical detection.
Streaming tables are in [stream benchmark](../../lab/zip-protocol/results/stream_benchmark.md)
and [coverage](../../lab/zip-protocol/results/coverage.md).

## 11. Positive findings
Independent frames, CRC, atomic restore, safe path rejection and folder
byte-equality worked. The core correctness suite remains reproducible.

## 12. Negative findings
Frame independence loses laws crossing boundaries. With scanning disabled the
formula component contributes nothing, so those ratio results cannot support a
mathematical-compression claim. The later [audit](03-audit.md) quantifies this.

## 13. Implementation limitations
Frame-probe budgets are small; copy state is local; native scanning is an
optional accelerator; historical folder commands assume external directories.

## 14. Theoretical limitations
A per-frame compressor cannot exploit dependencies across a frame boundary
without shared state. A finite probe budget leaves possible laws unobserved.

## 15. Conclusions
SXZ2 supplied a streaming and container substrate. Its large folder result was
superseded as evidence for formula discovery because the engine was off.

## 16. Reproduction instructions
Run the core tests and `examples/demo.py` from the
[reproduction guide](../../docs/reproduction.md). Historical large benchmark
inputs are unavailable for public reconstruction.
