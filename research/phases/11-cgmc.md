# Phase 11 - Contextual Generative Mosaic Compression (CGMC)

## 1. Research question

Can a context-conditioned bank of exact mathematical generators describe real
file spans economically, and can a learned selector improve that search without
overfitting or unsafe decoding?

## 2. Mathematical formulation

CGMC indexes a bounded bank of generators (constants, recurrences, short
programs, fitted predictors and history references) against byte contexts. A
span is accepted only when its generated bytes are exact; a strict control keeps
the literal and metadata frames byte-identical while replacing selected bytes
with generator references. The archive is a literal frame, a metadata frame and
explicit span references. Residuals are not used for the strict exact claim.

The v3 container adds a 72-byte header and a SHA-256 of the whole archive. The
older v2 container remains decodable. The 40-byte increase is charged in every
v3 comparison.

## 3. Dataset and protocol

The panel contains 25 existing real files (18,411,123 B): Canterbury/Calgary
texts, XML, executables, PDF, BMP/PNG/JPEG, WAV/FLAC/MP3/MP4, archives and
model-weight slices. The development/held-out split and SHA-256 values are in
`lab/sxz-cgmc/results/` and `datasets/provenance.json`. Large files were sliced
to a documented local size; complete-file claims are not made where slices were
used.

Baselines were matched on the same inputs and boundaries: direct zstd-19,
LZMA2, the SXZ4 transform/backend pipeline, literal control B (whole file in the
literal stream) and strict control C (byte-identical literal and metadata frames,
selected bytes removed separately). Search limits were fixed before the final
run; the native index and Python decoder were both tested.

## 4. Results

- 25 files; 18,411,123 B; dev 3,615,735 B; held-out 11,387,516 B; secondary
  3,407,872 B.
- 2,301,382 grid positions and 73,644,224 mathematical probes.
- Zero 8-byte mathematical matches; longest observed match was 4 bytes.
- Approximate matching found 0 candidates at Hamming distance <=2 over
  1,952,448 evaluations.
- 0/13 held-out files passed the predeclared `max(128 B, 1%)` gate.
- Strict controls: literal and metadata frames were byte-identical in 33/33
  checks. This isolates generator replacement from segmentation and backend
  effects.
- `fit8` v3 examples: BMP +682 B on development; notepad +19 B held-out;
  flac/png -35 B (the historical +5 B v2 wins were consumed by the 40-byte v3
  integrity header).
- `hist8` v3 BMP: G-C +21,654 B but G-A -1,398 B; notepad +5,146 B but
  -1,895 B. The replacement value exists, but segmentation/context loss is
  larger.
- Exact constants/periodic structure remains conventional; no new positive
  mathematical-compression claim is supported.

## 5. Learned selection and independent validation

A learned ranker reached independent-file AUC 0.777 / 0.941 / 0.720 on three
held-out files. Its 97.6% figure is ranking recall, not archive gain. At equal
archive size, learned selection was 2.8-3.3x slower (for example 9.78 s versus
2.92 s on notepad) because feature extraction and inference dominate. No
practical acceleration was demonstrated.

## 6. Long-range diagnostic

On a 16 MiB enwik8 slice: zstd-19 4,627,114 B; long-window zstd 4,604,369 B;
zstd-22 4,591,370 B; Brotli-11 4,465,120 B; LZMA2 4,480,976 B; CGMC history
4,627,856 B. CGMC was 742 B worse than default zstd and 23,487 B worse than the
matched long-window baseline. On a constructed 1 MiB-repeat file it beat default
zstd by 2,097,085 B, was 72 B smaller than long-window zstd and 303 B larger
than Brotli. The gain is conventional long-distance matching, not an independent
mathematical advantage.

## 7. Security and audit corrections

The original Appendix J "huge declared output accepted" result was a test
construction error: `craft(..., ntok=1)` left `orig_len=0`, so the decoder
correctly accepted an empty output. It was not a bypass. The audit did find real
resource gaps: `payload_len`, `ntok` and `meta_len` were not bounded before
decompression. Hardened v2/v3 now enforce a 256 MiB default output cap, token and
metadata caps, offset/length checks, frame-length checks and trailing-data
rejection.

The corrected 17-case malicious suite rejects payload/meta bombs, zero-length
tokens, oversized references, bad checksums and frame-length lies with
`ValueError`; the v3 positive control is accepted. The original result is
preserved in `lab/sxz-cgmc/results/audit-tests.json` as historical evidence.

## 8. Positive findings

Exact generator replacement works when a planted/structured law exists; strict
attribution is possible; the decoder hardening and checksum are correct; exact
synthetic controls and periodic/reference slices reconstruct; the audit resolved
a misleading security claim without hiding it.

## 9. Negative findings and limitations

No real file passed the economic gate. The learned selector is a ranking
component, not a compressor. Long-range results are explained by existing
long-window matching. The panel is mixed public/private and some inputs are not
redistributable; full historical reproduction is not one command. The branch was
stopped; no production decoder or general-purpose claim was made.

## 10. Reproduction

From the repository root:

```text
cd lab/sxz-cgmc
python -B scripts/test_codec.py
python -B scripts/audit_tests.py
```

`test_codec.py` exercises round trips, strict identity and malformed inputs;
`audit_tests.py` regenerates the compact security outcomes. The panel runner
requires the reviewed inputs; see `lab/sxz-cgmc/README.md`. Raw tables:
`lab/sxz-cgmc/results/strict-control-summary.json`,
`math-audit.json`, `ml-validation.json`, `approx.json`,
`long-range.json`, `long-range-synth.json`, `audit-tests.json`.
